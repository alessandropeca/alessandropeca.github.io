Standardized Labels

All raw catalog classification values are mapped to one of 10 standardized labels:

LabelDescription
type1Broad-line AGN (Seyfert 1, BLAGN, NLS1, QSO with broad lines)
type2Narrow-line AGN (Seyfert 2, NLAGN, Seyfert 1.5–1.9)
generic_agnAGN without broad/narrow distinction (QSO, LINER, generic AGN, BAL QSO, beamed AGN, unknown AGN subtype)
blazarBL Lac objects, FSRQs, OVV quasars, blazar candnameates
dual/mergerDual AGN, merging AGN pairs, galaxy pairs, galaxy interactions
galaxyNon-AGN galaxies (elliptical, spiral, starburst, emission-line galaxies, radio galaxies)
clusterGalaxy clusters, groups, compact groups (GClstr, GGroup, etc.)
starStars of all types (main sequence, white dwarfs, CVs, XRBs, pulsars, SNR, planetary nebulae, variable stars, globular clusters, open clusters)
lens_systemGravitational lens systems (lensed QSOs, lensed galaxies, lens candnameates)
unknownUnidentified, ambiguous, or unclassifiable sources (mixed star+galaxy, featureless spectra, wavelength-band detections without type, gamma-ray sources)

CLASSIFICATION TIERS (priority order)

Tiers and Merge Methods

  • spec_class: Spectroscopic classification (Merge method: provenance array)
  • SED_class: SED-fitting classification (Merge method: provenance array)
  • xray_class: X-ray morphology [point/extended] (Merge method: provenance array)
  • image_class: Optical image morphology (Merge method: provenance array)
  • gen_class: General/catalog-level classification (Merge method: provenance array)

Each source can have classifications in up to 5 tiers. The best_class is selected by priority:
spec_class > SED_class > xray_class > image_class > gen_class.

Pipeline Storage Variables

  • tier_all — JSON array of all classification values for that source
  • tier_origin — JSON array of catalog IDs contributing each value
  • tier_sub_all — JSON array of finer sub-classifications (e.g. "sy1.5", "bllac"), for every tier EXCEPT gen_class, which has no sub-classification column. best_class also carries a best_class_sub_all.

IMPLICIT CLASSIFICATION (via angular_resolution.json)

Catalogs that declare implicit_class in their angular_resolution.json get a virtual gen_class column injected by Stage 5 (build_table_from_cat.py) with the constant class value below. Most are AGN-specific surveys with no classification column of their own; a few (BAT-105M, Swift_BAT_157) also carry a real class column listed in section 3 and receive the implicit value on top of it.

best_class SELECTION

For each source, best_class is chosen from the highest-priority tier that has a non-unknown classification:

Priority: spec_class > SED_class > xray_class > image_class > gen_class

  • If all tiers are "unknown", best_class = "unknown".
  • If no tier has any classification, best_class is null (unclassified).

POST-CLASSIFICATION FLAGS

galaxy_only_flag (Stage 7.52 — flag_galaxy_only.py)

  • True when: source has classification, has "galaxy" in at least one tier, and NO tier contains an AGN-type label (type1, type2, generic_agn, blazar, lens_system, dual/merger) OR a "star" label.
  • Purpose: These may be buried/obscured AGN where nuclear activity is undetected. Kept in table but flagged for caution.

unknown_only_flag (Stage 7.52 — flag_galaxy_only.py)

  • True when: the source carries no usable classification — either every reported value across all five tiers is "unknown", OR no tier reports any classification at all (2026-07-11 change: previously True only for the all-"unknown" case, which under-covered the never-classified population).
  • Purpose: Sources with no usable type; prime candidates for follow-up.
  • NOTE: "unknown" is preserved as a real label in the _all provenance arrays (not converted to NaN), so the raw arrays still distinguish "observed but unclassifiable" (explicit "unknown") from "never observed" (empty arrays) even though the flag covers both.

in_galactic_plane (Stage 7.55 — galactic_plane_filter.py)

  • True when: |galactic latitude b| < 10 degrees.
  • Purpose: Stellar contamination, extinction, and source confusion elevated.

Star flagging (Stage 7.5 — filter_stars.py)

Sources are NOT removed. Each row gets a star_flag enum (confirmed / likely / unlikely / none); see pipeline_stages_description.md for the decision rules. Consumers filter at their chosen strictness (e.g. star_flag == 'none' for the strictest AGN/galaxy sample).
